## 1. 产品概述

位置守护是一款面向好友、情侣和家人的轻量位置陪伴工具。用户仅与明确绑定并持续授权的关系分享实时位置、在线状态、运动状态及必要的设备状态，并可通过到家提醒、强提醒和“戳一戳”等低成本互动减少反复询问。

产品不是监控工具。所有位置能力必须建立在可理解、可撤回、可感知的授权之上；当数据不新鲜、权限关闭或好友离线时，界面必须如实表达，不得用推测位置制造“仍在实时定位”的错觉。

### 1.1 一句话价值主张

和在意的人共享当下，少一点担心，多一点安心。

### 1.2 核心价值

1. **建立信任**：好友关系双向确认，位置共享随时可暂停或撤回。
2. **实时陪伴**：在地图上快速理解对方位置、在线状态和运动状态。
3. **安全反馈**：通过到家报平安、强提醒、快捷规则降低紧急或晚归场景下的沟通成本。
4. **隐私最小化**：实时位置只通过私有客户端 Broadcast 瞬时转发，不进入业务数据库或可回放历史；本地轨迹有明确保留周期并可清除。

## 2. 背景与用户问题

### 2.1 用户问题

- 晚归、长途出行或独自行动时，需要反复发送“到哪了”“到家了吗”。
- 传统定位产品容易产生被监控感，用户不知道谁能看、何时在看、数据保存多久。
- 普通聊天消息在紧急时刻可能被忽略，缺少轻量但醒目的联系手段。
- 位置、在线、电量、网络等信息分散，无法快速判断“对方安全但不方便回复”还是“可能需要帮助”。

### 2.2 产品机会

以小规模、强关系、明确授权为边界，把地图、状态和自动报平安整合到一个移动端入口中；用温暖的视觉语言和清晰的隐私机制，提供“陪伴而非监控”的体验。

## 3. 产品目标与非目标

### 3.1 V1 目标

- 新用户可以在 5 分钟内完成登录、权限理解、添加首位好友并开始位置共享。
- 用户保持页面活跃且双方在线时，好友位置可被稳定获取，并始终展示更新时间与精度状态。
- 用户可一键暂停位置共享、删除好友或清除本地数据。
- 在线强提醒和戳一戳可在可控频率下可靠送达。
- 建立“家庭/学校/公司”等常用地点，为到家报平安等自动化能力提供基础。
- 以 Render Static Site + Supabase 的低运维方案完成私有部署，服务固定的小规模受邀用户。

### 3.2 非目标

- 不做公开附近的人、陌生人发现、内容广场或社交动态。
- 不做未经授权的定位、隐藏定位、设备控制或取证追踪。
- V1 不提供完整即时聊天、群聊、语音或视频通话系统。
- V1 不在服务端保存可回放的连续历史轨迹。
- V1 Web 版不承诺退到后台、锁屏或浏览器冻结后的持续定位；需要后台实时定位时进入原生化版本。
- V1 不承诺在中国大陆持续可访问或达到紧急服务级别；跨境网络波动时允许位置延迟或暂时不可用。
- “假装来电”仅用于日常脱身，不替代报警、急救或专业安全服务。

## 4. 目标用户与典型场景

### 4.1 目标用户

| 用户类型 | 主要诉求 | 关键顾虑 |
| --- | --- | --- |
| 年轻好友 | 聚会后互相确认安全、会合找人 | 不想频繁报备，不想被长期追踪 |
| 情侣 | 通勤、晚归时减少重复询问 | 希望表达关心而非控制 |
| 家人 | 掌握出行状态、确认到家 | 操作简单、状态可信、异常能提醒 |

### 4.2 核心场景

1. **通勤陪伴**：用户打开地图查看好友正在步行、乘车或停留，以及最后更新时间。
2. **到家报平安**：用户进入已设定的“家”范围后，系统向指定好友发送简短通知。
3. **晚归关心**：深夜仍未到家时触发自定义规则，提示本人或通知指定好友。
4. **临时联系**：用户双击好友头像戳一戳；需要更强反馈时发送强提醒。
5. **会合与导航**：从好友详情查看距离并唤起外部地图导航。
6. **安全脱身**：用户手动启动模拟来电界面，借机离开不适场景。
7. **撤回共享**：用户临时暂停全局或单个好友的位置共享，并看到清晰的生效结果。

## 5. 产品原则

1. **默认克制**：仅收集实现当前功能所需的数据，不默认长期保存位置。
2. **持续同意**：一次授权不等于永久授权；共享状态必须随时可见、可暂停、可撤回。
3. **状态真实**：在线、离线、延迟、无权限、精度不足分别展示，不混用。
4. **双向关系**：好友添加必须由双方确认；删除或拉黑后立即停止互相访问位置。
5. **降低焦虑**：文案描述事实，不使用“失联”“异常”等未经证实的恐吓表达。
6. **安全优先**：任何客户端参数都不能替代服务端鉴权和好友关系校验。

## 6. 版本范围与优先级

### 6.1 P0：V1 必须交付

- Supabase 邮箱＋密码登录、会话管理与退出登录；关闭公开注册，由管理员预先创建受邀账号。
- 首次使用引导：定位、通知和隐私说明，允许跳过非必要权限。
- 邀请码添加好友、双方确认、备注、删除和拉黑。
- 全局及单好友位置共享开关。
- 实时地图：自己与好友位置、在线状态、运动状态、位置精度、更新时间。
- 好友详情：距离、电量、充电、网络、设备、停留时长及快捷操作。
- 在线强提醒、戳一戳及频率限制。
- 个人资料、隐私设置、本地数据清除、账号注销入口。
- Supabase Auth 鉴权、业务表与私有频道 RLS、实时位置不落库及传输加密。
- Supabase PostgreSQL 保存账号资料、好友关系和共享授权，Supabase Auth 管理身份与会话。
- Supabase Realtime 私有 Broadcast 传递位置、戳一戳和强提醒，Presence 表示在线状态；实时位置不写入 PostgreSQL。
- Render Static Site 托管 React/Vite 静态前端，不部署 Render Web Service，移除生产环境对 NestJS 常驻进程、Socket.IO 和进程内状态的依赖。
- 使用 Render HTTPS 域名或自定义域名，Supabase 项目选择新加坡区域。
- 数据访问通过应用侧 Gateway/Repository 封装，核心表结构和迁移由项目管理，避免页面组件直接依赖 Supabase 查询细节。
- 权限拒绝、断网、好友离线、数据延迟等完整异常状态。

### 6.2 P1：V1.1 增强

- 常用地点与地理围栏。
- 到家报平安、深夜未到家、出门通知等快捷规则。
- 仅保存在本机的 7 天轨迹与日期筛选。
- 外部导航、拨号、天气信息、听歌状态。
- 模拟来电、主题切换、自定义敏感词。

### 6.3 P2：后续评估

- 多人临时同行圈、共享时长倒计时。
- 端到端加密的位置转发方案。
- 离线推送、可验证的消息送达回执。
- 更细粒度的共享内容控制，如仅共享大致区域、不共享电量。
- 基于 Capacitor 原生插件或 React Native 的后台定位、锁屏持续上报和原生推送。

## 7. 信息架构

全局仅保留一套底部导航：

| Tab | 核心内容 |
| --- | --- |
| 地图 | 实时地图、自身状态、好友标记、地点、共享控制 |
| 好友 | 好友列表、在线/离线分组、搜索、邀请和添加 |
| 快捷指令 | 自动报平安规则、模板、启停和编辑 |
| 我的 | 个人资料、状态、隐私、主题、辅助安全工具与数据管理 |

好友详情、添加好友、模拟来电等作为二级页面进入。V1 不设置独立“消息”Tab；强提醒与系统反馈以即时通知形式呈现。

## 8. 核心用户流程

### 8.1 首次激活

管理员预创建受邀账号 → 用户使用邮箱和密码登录 → 首次修改临时密码 → 阅读定位用途 → 选择允许或暂不开启 → 阅读通知用途 → 隐私承诺 → 进入地图 → 确认好友关系与共享授权。

### 8.2 查看好友位置

进入地图 → 系统同步好友与在线状态 → 选择好友标记 → 查看位置更新时间/精度 → 进入好友详情 → 选择导航、拨号、天气或提醒。

### 8.3 到家自动报平安

创建“家”地点 → 选择到家模板 → 选择接收好友 → 确认触发条件和通知内容 → 开启规则 → 进入地理围栏 → 本地规则判断 → 在线转发通知 → 展示触发结果。

### 8.4 撤回位置共享

打开地图或隐私设置 → 暂停全局共享或关闭指定好友 → 二次确认影响 → 服务端立即撤销读取权限 → 好友端显示“对方已暂停共享”，不得继续展示旧位置为实时位置。

## 9. 详细功能需求

### 9.1 账号与首次引导

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| AUTH-01 | P0 | 受邀账号登录 | 关闭公开注册；管理员在 Supabase Auth 中预创建用户，用户使用邮箱和密码登录；首次登录必须修改临时密码。 |
| AUTH-02 | P0 | 会话安全 | 使用 Supabase Auth 签发和刷新会话；退出后清理本地会话；管理员禁用账号时将 `profiles.enabled` 设为 false，使 RLS 在旧 JWT 到期前也能阻止数据库和 Realtime 访问。 |
| AUTH-03 | P0 | 首次引导 | 依次说明定位、通知和隐私用途；用户可跳过通知，跳过定位后仍可进入只读空状态。 |
| AUTH-04 | P0 | 权限补救 | 权限被拒绝时展示原因、受影响功能及系统设置指引，不反复弹系统授权框。 |
| AUTH-05 | P0 | 使用说明确认 | 登录前可查看隐私说明和使用限制，并记录确认版本与时间；明确产品仅供朋友间自用且不承担紧急救援职责。 |

### 9.2 好友关系

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FRIEND-01 | P0 | 生成好友绑定码 | 仅已登录的受邀账号可生成短时绑定码；旧码刷新后失效；绑定码只能关联现有账号，不能用于公开注册。 |
| FRIEND-02 | P0 | 添加与确认 | 输入绑定码后显示最小必要资料；被邀请方确认后才建立双向好友关系，位置共享仍需单独确认。 |
| FRIEND-03 | P0 | 好友列表 | 在线优先，离线次之；展示头像、昵称/备注、在线状态、运动状态和最后更新时间。 |
| FRIEND-04 | P0 | 备注、删除与拉黑 | 备注仅本人可见；删除后双方位置权限立即撤销；拉黑后不可再次邀请，除非主动解除。 |
| FRIEND-05 | P0 | 空与错误状态 | 无好友时引导邀请；邀请码无效、过期、已添加、本人邀请码分别给出明确反馈。 |

### 9.3 位置采集、共享与地图

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| LOC-01 | P0 | 位置采集 | 用户授权并开启共享后采集；V1 仅承诺页面处于活跃前台时工作；移动状态建议每 5 秒上报，静止、弱网或页面不可见时动态降频或停止，并向用户如实说明。 |
| LOC-02 | P0 | 实时位置传递 | 使用 Supabase Realtime 客户端私有 Broadcast 直接发送实时位置，关闭 replay，不使用数据库触发器广播；位置不写入 PostgreSQL、`realtime.messages` 历史、文件日志、错误追踪或分析平台。新订阅者等待下一次上报，目标等待时间不超过 5 秒。 |
| LOC-03 | P0 | 好友访问控制 | 所有位置频道均为私有频道；通过 Supabase Auth JWT 和 `realtime.messages` RLS 同时校验双向好友关系、拉黑状态和共享授权；任一条件失效后禁止重新订阅并主动断开现有订阅。 |
| LOC-04 | P0 | 地图标记 | 标记展示头像、在线/离线及步行、跑步、乘车、停留状态；点击进入预览，双击触发戳一戳。 |
| LOC-05 | P0 | 新鲜度表达 | 0–30 秒显示“刚刚更新”；31 秒–2 分钟显示具体时间；超过 2 分钟标记“位置延迟”；离线或暂停后不得称为实时位置。 |
| LOC-06 | P0 | 精度表达 | 展示 GPS 精度数值或范围；精度差时显示半透明范围圈与“定位精度较低”。 |
| LOC-07 | P0 | 地图控制 | 支持回到本人位置、地图图层切换、好友聚焦和屏外好友方向提示；控件不遮挡核心地图信息。 |
| LOC-08 | P0 | 共享控制 | 提供全局与单好友开关；关闭后 2 秒内停止新的位置转发，并使好友端进入“已暂停共享”状态。 |
| LOC-09 | P0 | 故障降级 | 断网、地图 SDK 失败或定位不可用时保留可操作页面，并展示重试或设置入口。 |

### 9.4 状态与好友详情

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| DETAIL-01 | P0 | 顶部信息 | 展示头像、昵称/备注、在线状态、运动状态、当前位置描述和更新时间。 |
| DETAIL-02 | P0 | 设备状态 | 在设备支持时展示电量、充电状态、网络类型和设备机型；不支持时显示“暂不可用”，不得伪造。 |
| DETAIL-03 | P0 | 距离与精度 | 基于双方最新有效位置计算直线距离，并明确为估算；同时展示好友 GPS 精度。 |
| DETAIL-04 | P1 | 停留与轨迹 | 展示当前地点停留时长；历史轨迹仅保存在产生轨迹的本机，默认保留 7 天，可按日期查看和全部清除。 |
| DETAIL-05 | P1 | 听歌状态 | 仅在用户主动开启后展示音乐应用与歌曲；支持一键关闭，关闭后不再上报。 |
| DETAIL-06 | P1 | 快捷操作 | 支持系统拨号、外部地图导航、当前地点天气和强提醒；跳转前明确目标好友和外部应用。 |

### 9.5 提醒与轻互动

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| ALERT-01 | P0 | 戳一戳 | 双击好友标记发送；同一发送者对同一接收者 30 秒最多 1 次；双方均有清晰视觉反馈。 |
| ALERT-02 | P0 | 强提醒 | 用户确认后发送标题和内容；标题、内容分别限制为 6 个中文字符等价长度；仅对有效好友开放。 |
| ALERT-03 | P0 | 在线送达状态 | 接收方在线时展示应用内通知并尝试系统通知/震动；发送方看到“已送达”或“发送失败”，不得将服务端接收等同于用户已读。 |
| ALERT-04 | P0 | 频控与滥用防护 | 对发送者、接收者和关系维度限流；被拉黑或已删除关系不得发送；连续失败时给出冷却时间。 |
| ALERT-05 | P2 | 离线推送 | 接入系统推送后支持离线送达；上线前若未实现，明确提示“对方离线，未送达”。 |

### 9.6 常用地点与快捷指令

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| PLACE-01 | P1 | 地点管理 | 用户可创建家庭、公司、学校或其他地点，编辑名称、地址、坐标和围栏半径，默认半径 200 米。 |
| PLACE-02 | P1 | 围栏判断 | 位置进入/离开围栏需采用去抖和精度校验，避免 GPS 漂移反复触发。 |
| RULE-01 | P1 | 规则模板 | 提供“到家自动报平安”“深夜未到家提醒”“出门自动通知”模板。 |
| RULE-02 | P1 | 自定义规则 | 支持时间、地点和本人状态条件，以及通知指定好友的动作；用户可编辑、启停和删除。 |
| RULE-03 | P1 | 触发去重 | 同一条件持续满足期间只触发一次；条件退出并再次满足后才允许再次触发。 |
| RULE-04 | P1 | 可解释性 | 每条规则展示条件、动作、接收者、上次触发时间和失败原因。 |
| RULE-05 | P1 | 本地执行说明 | V1 规则引擎在应用运行时本地执行；若后台无法保证运行，创建规则时必须说明限制。 |

### 9.7 个人中心、隐私与辅助安全

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| PROFILE-01 | P0 | 个人资料 | 支持头像、昵称和自定义状态；昵称及状态经过长度和内容校验。 |
| PROFILE-02 | P0 | 隐私面板 | 展示当前共享状态、可查看位置的好友、权限状态、数据保存位置和保留期限。 |
| PROFILE-03 | P0 | 数据清除 | 可分别清除本地轨迹、地点、规则和全部本地数据；操作前列明影响并二次确认。 |
| PROFILE-04 | P0 | 账号注销 | 提供注销入口；完成身份校验后删除账号关系及服务端持久数据，并立即撤销令牌。 |
| PROFILE-05 | P1 | 模拟来电 | 用户手动启动、接听和挂断模拟界面；不得冒充真实运营商呼叫或自动联系第三方。 |
| PROFILE-06 | P1 | 辅助设置 | 支持浅色、深色和跟随系统主题；敏感词只用于本人创建的文本内容过滤。 |

## 10. 状态定义与交互文案

| 状态 | 判定 | 推荐表达 |
| --- | --- | --- |
| 在线且位置新鲜 | WebSocket 在线，最近位置 ≤ 30 秒 | “在线 · 刚刚更新” |
| 在线但位置延迟 | 在线，最近位置 > 2 分钟 | “在线 · 位置延迟” |
| 离线 | 连接断开 | “离线 · 最后更新于 HH:mm” |
| 暂停共享 | 对方主动关闭共享 | “对方已暂停位置共享” |
| 无定位权限 | 本机权限被拒绝或系统关闭 | “定位未开启” |
| 精度较低 | accuracy 超过产品阈值 | “定位精度较低，位置仅供参考” |
| 无历史位置 | 无可合法展示的快照 | “暂无位置” |

禁止使用未经事实支持的文案，如“对方失联”“对方有危险”“位置异常”。

## 11. 数据模型与数据生命周期

| 数据对象 | 关键字段 | 存储位置 | 生命周期 |
| --- | --- | --- | --- |
| 用户 User | userId、昵称、头像、状态、enabled、创建时间 | Supabase PostgreSQL `public.profiles` | 至管理员删除账号或用户主动清除；enabled=false 时立即失去业务权限 |
| 认证身份 AuthIdentity | userId、邮箱、验证状态 | Supabase Auth `auth.users` | 至管理员删除账号 |
| 会话 Session | Supabase Auth 管理的访问令牌与刷新令牌 | Supabase Auth | 到期、退出、密码变更或账号禁用后失效 |
| 好友关系 Friendship | 双方 userId、关系状态、创建时间 | Supabase PostgreSQL | 至删除、拉黑或任一账号删除 |
| 共享授权 ShareConsent | 授权方、接收方、开关、更新时间 | Supabase PostgreSQL | 撤回后立即失效，保留不含位置的最小审计记录 |
| 好友绑定码 InviteCode | 随机码摘要、创建者、有效期、使用状态 | Supabase PostgreSQL | 使用或过期后清理 |
| 拉黑关系 Block | 发起者、被拉黑者、创建时间 | Supabase PostgreSQL | 至主动解除或账号删除 |
| 实时位置 LocationBroadcast | 经纬度、精度、运动、电量、网络、更新时间 | Supabase Realtime 私有客户端 Broadcast | 不进入业务表，不启用 replay；只对当时在线且有权限的订阅者可见 |
| 在线状态 Presence | userId、连接状态、更新时间 | Supabase Realtime Presence | 连接期间保留，断开后由 Presence 移除 |
| 本地轨迹 TrajectoryPoint | 坐标、精度、时间、日期 | 用户设备 IndexedDB | 默认 7 天，可随时清除 |
| 常用地点 Place | 名称、坐标、半径、标签 | 用户设备；跨端同步另行评审 | 至用户删除或清除数据 |
| 快捷规则 ShortcutRule | 条件、动作、接收者、启停状态 | 用户设备；跨端同步另行评审 | 至用户删除或清除数据 |
| 提醒事件 Alert/Poke | 发送者、接收者、消息 ID、时间、最小内容 | Supabase Realtime 私有 Broadcast | P0 不做历史持久化；由客户端维护短期冷却和消息去重 |

Supabase PostgreSQL 是资料、关系和授权的权威数据源；IndexedDB 只能作为缓存或明确声明为“仅本机”的数据存储，不能作为好友关系和共享权限的唯一依据。产品文案必须准确说明：实时位置会经 Supabase Realtime 做瞬时转发，但不会进入业务数据库或形成服务端历史轨迹。不得表述为“位置从不经过服务器”。

## 12. 权限、隐私与安全要求

### 12.1 权限矩阵

| 权限/能力 | 申请时机 | 拒绝后的可用能力 |
| --- | --- | --- |
| 定位 | 用户完成用途说明并点击“允许定位” | 可管理好友和设置，不能共享本人位置 |
| 通知 | 用户完成通知用途说明后主动开启 | 仍可接收应用内提醒，不保证后台提醒 |
| 震动 | 随提醒使用，不单独强求 | 仅展示视觉反馈 |
| 电量/网络信息 | 功能使用时按浏览器支持读取 | 对好友显示“暂不可用” |

### 12.2 安全基线

- 全部 HTTP 与 WebSocket 通信使用 TLS。
- Supabase 数据和 Realtime 私有频道必须验证 Auth JWT，不接受仅“非空 token”校验。
- userId 仅使用 JWT 中的 `auth.uid()`，不信任客户端自报 userId。
- 好友资料、共享授权及 Realtime 频道的 SELECT/INSERT 均启用 RLS，默认拒绝，按有效好友和共享授权显式放行。
- 经纬度不得出现在应用日志、错误追踪、分析事件或第三方埋点参数中。
- 邀请码使用高熵随机值、短期有效、单次或限次使用，并限制尝试频率。
- 对接口、WebSocket 事件和通知实施限流、参数校验、重放保护与消息 ID 去重。
- Supabase PostgreSQL 内不建立原始位置历史表；数据库备份同样不得包含实时经纬度。
- 位置只使用客户端 Broadcast，禁止通过数据库触发器、`realtime.send()` 或 Broadcast Replay 发送，以免形成可回放记录。
- 撤回共享、删除好友、拉黑或删除账号时，立即移除客户端频道订阅并使对应 RLS 授权失效。
- 清晰展示共享指示，至少在地图页和隐私设置页可见；关闭共享无需寻找深层入口。
- 隐私政策应说明数据类别、用途、处理位置、保留期、第三方 SDK 和用户权利。

## 13. 技术架构与数据库独立性

### 13.1 架构决策

V1 采用 Render Static Site + Supabase 的托管架构，不保留生产环境常驻 NestJS/Socket.IO 服务：

- **Render Static Site**：构建和托管 React + Vite 静态前端；不运行会休眠的免费 Web Service，也不持有任何服务端密钥。
- **Supabase Auth**：管理受邀邮箱账号、密码、JWT 和会话；关闭公开注册。
- **Supabase PostgreSQL**：保存资料、好友关系、绑定码、拉黑和共享授权，并使用 RLS 执行数据访问控制。
- **Supabase Realtime Broadcast**：传递高频实时位置、戳一戳和强提醒。
- **Supabase Realtime Presence**：同步在线/离线等低频连接状态，不用于高频位置更新。
- **Supabase Storage**：可选保存头像；头像桶默认为私有并受用户权限控制。
- **IndexedDB**：保存本地缓存和本机 7 天轨迹，不作为好友关系或授权的权威来源。

Supabase 项目选择新加坡 `ap-southeast-1`。前端静态资源由 Render Static Site CDN 分发；Render 与 Supabase 都没有中国大陆计算节点，中国大陆可用性只做尽力而为保证。

### 13.2 账号与数据访问边界

- 管理员预创建固定成员账号并分发临时密码；关闭公开注册、手机 OTP 和第三方社交登录。
- 登录、刷新会话、退出和密码变更统一通过 Supabase Auth；页面不得继续生成本地 userId 或随机 token。
- `public.profiles.id` 与 `auth.users.id` 一一对应，所有业务表外键均引用用户 UUID；`profiles.enabled` 是 RLS 的强制条件，用于立即停用成员。
- 所有 `public` 业务表启用 RLS，并先采用默认拒绝策略；用户只能访问本人资料、与本人有关的好友关系和明确授权的数据。
- 管理操作如预创建账号、禁用账号或修复关系，只能在 Supabase Dashboard 或受保护的本地管理脚本中使用 Supabase secret key；secret key 绝不能进入 Render 的 `VITE_*` 环境变量或前端构建产物。

### 13.3 Realtime 私有频道设计

| 频道 | 用途 | 发送权限 | 接收权限 |
| --- | --- | --- | --- |
| `user:{ownerId}:location` | 本人实时位置 | 仅 `auth.uid() = ownerId` | 与 owner 存在有效好友关系、未拉黑且有共享授权 |
| `user:{receiverId}:notifications` | 戳一戳和强提醒 | 有效好友且未被拉黑 | 仅 `auth.uid() = receiverId` |
| `friends:{userId}:presence` | 好友在线状态 | 仅本人 track | 有效好友 |

- 所有生产频道使用 `private: true`，通过 `realtime.messages` 的 SELECT/INSERT RLS 和 `realtime.topic()` 校验频道权限。
- 高频位置使用客户端 Broadcast；不使用 Presence 承载位置，不使用 Postgres Changes、数据库触发器、`realtime.send()` 或 Broadcast Replay 传递位置。
- 位置不保存最新服务端快照。好友新加入频道后等待下一次广播，正常前台移动状态下最长约 5 秒。
- 共享授权关闭、删除好友或拉黑后，客户端立即退订频道；RLS 同时阻止重新加入。
- Broadcast 失败、频道断开或权限被拒绝时，界面进入“位置延迟/暂不可用”，不得继续显示为实时状态。

### 13.4 数据库独立性与迁移

V1 接受 Supabase Auth 和 Realtime 的平台耦合，但核心业务数据保持 PostgreSQL 可迁移：

- 核心表使用标准 PostgreSQL 类型，不使用平台专属 `user_profile`、`file_attachment` 等自定义类型。
- 表结构、函数、索引和 RLS 使用 Supabase CLI migration 文件版本化管理，不只保存在在线控制台。
- 页面和 Hooks 不直接散落 Supabase 查询；统一依赖 `AuthGateway`、`ProfileRepository`、`FriendshipRepository`、`InviteRepository`、`BlockRepository` 和 `ShareConsentRepository`。
- 当前提供 Supabase 适配器；未来更换 PostgreSQL 托管商时，业务组件无需改写，只替换数据适配器和认证/实时实现。
- 实时位置不进入 PostgreSQL，因此数据库导出、备份和迁移不应包含经纬度历史。

### 13.5 Render 与中国大陆访问策略

- 可以先使用 `*.onrender.com` HTTPS 地址；如实测跨境访问不稳定，再绑定自定义域名并选择合适的 DNS 服务商。
- 自托管字体和关键静态资源，不依赖可能无法访问的第三方字体、分析或脚本域名。
- Supabase API、Auth 和 Realtime 统一使用项目 HTTPS/WSS 域名，并实现指数退避重连和显式离线状态。
- 首次发布前分别使用中国移动、联通、电信和家庭 Wi-Fi 做实际访问测试；测试结果只代表当时网络，不形成长期可用性保证。
- Render 和 Supabase 都没有中国大陆基础设施，跨境网络可能导致延迟、限速或不可访问。产品不得把该部署当作紧急救援、可靠报警或持续安全保障。
- 如两位用户位于香港或澳门，网络条件通常不同，但仍需实际测试。

### 13.6 环境变量与密钥

前端仅允许暴露：

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`
- `VITE_AMAP_KEY`
- `VITE_AMAP_SECURITY_CODE`

服务端或管理环境才允许配置：

- `SUPABASE_SECRET_KEY`
- 数据库连接串或迁移凭据

高德和 Supabase 公钥仍需配置域名白名单、配额和 RLS；“可公开出现在前端”不代表无需权限控制。

### 13.7 客户端本地存储边界

- IndexedDB 可缓存好友资料，但删除、拉黑和共享权限始终以 Supabase 返回结果为准。
- 缓存必须按 Supabase user UUID 分区；退出或切换账号时不得向新账号展示旧账号数据。
- 本地轨迹默认只在产生轨迹的设备保存 7 天，不参与好友权限判断，也不自动上传。
- localStorage 只保存非敏感偏好和 Supabase SDK 必需的会话数据；退出、禁用账号或清除数据后同步清理。

### 13.8 架构验收标准

1. 关闭公开注册后，未知用户无法自行创建账号或进入应用。
2. 未建立好友或未获得共享授权的账号不能加入他人的私有位置频道。
3. 已授权好友加入频道后，可在下一次位置广播周期内收到位置；数据库及 Realtime 可回放记录中不存在该经纬度。
4. 删除好友、拉黑或撤回共享后 2 秒内退订对应频道，并无法重新订阅。
5. 将 `profiles.enabled` 设为 false 后，即使旧 JWT 尚未到期，RLS 也立即阻止其访问业务表和私有频道；修改密码或退出后会话按 Supabase Auth 策略处理。
6. Supabase 或跨境网络不可用时，页面明确显示离线/位置延迟，不展示伪实时位置。
7. 使用自定义域名在双方实际使用的移动网络和 Wi-Fi 上完成登录、地图、Realtime 重连和退出测试。
8. 前端构建产物中不存在 Supabase secret key、数据库连接串或管理凭据。

## 14. 非功能需求

### 14.1 性能与稳定性

- 中国大陆跨境网络正常且缓存命中时，中端移动设备首屏可交互时间目标 ≤ 5 秒；网络不可达时应在 10 秒内展示明确错误状态。
- 双方前台在线且 Supabase Realtime 正常时，位置或提醒事件端到端 P95 延迟目标 ≤ 3 秒，不含系统定位产生时间；该指标不作为紧急服务承诺。
- 地图操作保持流畅；多好友标记使用聚合或视窗裁剪，避免主线程持续阻塞。
- Supabase Realtime 断开后指数退避重连；重连成功后重新获取会话、好友和共享授权，再加入私有频道。
- Render 仅发布静态文件，生产环境不运行应用服务端进程，也不在 Render 本地文件系统保存用户会话、好友关系或位置数据。
- Supabase API、Auth 和 Realtime 请求均配置超时、有限重试和离线反馈，避免跨境网络异常时无限等待。
- 不支持的浏览器 API 必须降级，不能导致页面崩溃。

### 14.2 电量与流量

- Web 版仅在页面活跃前台承诺实时采样；页面不可见、后台或系统冻结时停止承诺持续上报，并在界面展示位置可能延迟。
- 采样频率根据页面可见性、运动状态、精度和网络动态调整，禁止无条件长期 5 秒高精度定位。
- 相同或近似坐标不重复上报；状态字段变化可独立增量发送。
- 在产品设置中说明持续定位可能增加电量消耗。

### 14.3 可访问性与适配

- 正文颜色对比度至少 4.5:1，重要状态不能仅靠颜色区分。
- 交互元素具备可见 focus 状态和可读标签，主要点击区域不小于 44 × 44 px。
- 适配 320 px 起的移动端宽度与安全区；桌面端最大宽度约 448 px 居中展示。
- 动效遵循系统“减少动态效果”偏好；呼吸光晕不得影响文字可读性。

## 15. 视觉与内容规范

- 采用浅青灰背景、白色卡片和青绿主色，避免深色监控仪表盘感。
- 地图是主视觉，浮层使用半透明毛玻璃并控制面积。
- 好友头像标记配运动状态胶囊；在线态可使用 2 秒呼吸光晕，离线态降低饱和度。
- 底部导航使用非透明毛玻璃背景，激活态为青绿，未激活态为低饱和灰绿。
- 卡片圆角 12 px，状态切换 200 ms ease-out，页面转场 300 ms slide-up。
- 标题使用圆润无衬线字体，正文和数字优先保证地址、距离及状态的可读性。
- 文案强调“分享、陪伴、报平安”，避免“监控、掌控、追踪对方”等措辞。

## 17. 验收场景

1. 新用户拒绝定位后仍能完成引导，地图明确提示缺少权限并提供设置入口。
2. A 与 B 未成为好友时，即使 A 知道 B 的 userId，也无法读取 B 的位置或发送提醒。
3. A 与 B 建立好友并互相授权后，A 能看到 B 的新鲜位置、精度和更新时间。
4. B 关闭对 A 的共享后，A 在 2 秒内看到“已暂停共享”，服务端拒绝后续位置请求。
5. B 断网后，A 看到离线及最后更新时间，不继续播放实时移动效果。
6. 同一用户 30 秒内重复戳同一好友时，第二次被阻止并显示剩余冷却时间。
7. 强提醒接收方离线且未实现离线推送时，发送方明确看到“对方离线，未送达”。
8. 用户创建“到家报平安”规则，持续停留在围栏内只触发一次，离开并再次进入后才可再次触发。
9. 用户清除轨迹后，本机无法恢复相关点位，其他个人资料不受影响。
10. 用户删除好友、拉黑或禁用账号后，旧会话、旧绑定码和既有 Realtime 私有频道均不能继续访问位置。
11. A、B 使用不同运营商网络时，仍能按授权加入 Supabase 私有频道、查看位置并接收提醒；断开后可自动重连。
12. Supabase API 或 Realtime 暂时不可用时，新增好友、撤权或实时位置明确失败，不回退到仅依赖本地 IndexedDB 的权限判断。
13. 检查 Supabase 业务表、备份、数据库 Broadcast/Replay、日志和错误追踪，均不存在原始经纬度字段或值。
14. Web 页面进入后台后，产品不再展示“持续实时定位”的承诺，并根据最后更新时间进入延迟状态。
15. 使用自定义域名分别在双方常用的移动网络和家庭 Wi-Fi 完成首次加载、登录、地图及退出测试。
16. 关闭公开注册后，陌生邮箱无法自行创建账号；前端构建产物中不存在 secret key 或数据库连接串。

## 18. 当前原型与上线阻断项

以下内容基于当前代码现状，必须在生产发布前处理：

| 等级 | 现状 | 上线要求 |
| --- | --- | --- |
| Blocker | 验证码由前端随机生成并直接展示 | 删除模拟验证码，接入 Supabase 邮箱＋密码登录，关闭公开注册并预创建固定成员账号 |
| Blocker | WebSocket 仅校验客户端自报 userId/token | 移除生产环境 Socket.IO 网关，改用 Supabase Auth JWT 与 Realtime 私有频道 |
| Blocker | 好友关系主要保存在浏览器 IndexedDB | 建立 Supabase PostgreSQL 好友、绑定码、拉黑和共享授权表，并启用 RLS |
| Blocker | 好友位置请求未验证双方好友关系与共享授权 | 在 `realtime.messages` RLS 中按 `auth.uid()`、频道 topic、好友和授权关系校验 |
| Blocker | 服务端日志记录精确经纬度 | 移除坐标日志；位置仅走客户端 Broadcast，并验证数据库、Replay、日志和错误追踪均不接收坐标 |
| High | 位置快照、在线状态和限流仅在单进程内存中 | 删除生产环境进程内状态；位置改用 Broadcast，在线状态改用 Presence |
| High | 业务代码没有 Repository/Gateway 边界 | 建立 AuthGateway 和 Supabase Repository 适配器，页面组件不得散落数据库查询和 RLS 假设 |
| High | PlatformModule 自动集成平台数据库/认证，同时部署配置跳过数据库初始化 | Render 生产构建只输出 `dist/client` 静态文件，不启动 PlatformModule、ViewModule 或常驻 NestJS 入口；管理能力使用 Supabase Dashboard 或受保护脚本 |
| High | 强提醒/戳一戳离线即丢弃，发送方缺少可靠回执 | 增加结果回执；未做离线推送前明确展示未送达 |
| High | “所有数据不上传服务器”的文案与实时转发事实不一致 | 统一为“位置经 Supabase Realtime 瞬时转发，但不进入业务数据库或形成历史轨迹” |
| High | 尚未验证中国大陆访问 Render/Supabase 的稳定性 | 使用 Render HTTPS 地址或自定义域名，在双方常用移动网络和 Wi-Fi 上实测；产品明确为尽力而为可用性 |
| Medium | 常用地点、轨迹和快捷规则仅存本机 | 在产品中明确本地存储、跨设备不恢复及清除影响 |
| Medium | Web 版依赖 `watchPosition` 和页面定时器，无法保证锁屏或后台持续运行 | V1 明确只承诺前台实时；后台定位进入 Capacitor/React Native 原生化阶段 |
| Medium | 地图与天气密钥硬编码在客户端配置 | 改用 Render 构建环境变量，并配置域名白名单、配额和密钥轮换；secret key 不得暴露到前端 |
| Medium | 当前没有 Render SPA 路由与环境配置 | 增加 `render.yaml` Static Site 构建配置、`dist/client` 发布目录、环境变量和 SPA fallback |
| Medium | 当前没有自动化测试 | 补充 Supabase migration、业务表 RLS、Realtime 私有频道越权、撤权传播和前端重连测试 |

## 19. 发布计划建议

### 阶段 A：安全可用 MVP

创建新加坡 Supabase 项目，完成邮箱账号、关闭公开注册、SQL migrations、业务表 RLS、Realtime 私有频道、Repository/Gateway 边界、地图核心状态和隐私面板；通过 `render.yaml` 发布 Render Static Site、配置构建环境变量，并通过双方常用网络的越权、重连和位置不落库验收后开始自用。

### 阶段 B：陪伴体验增强

上线地点、快捷规则、本地 7 天轨迹、天气/导航/拨号和音乐状态；重点验证误触发率、电量消耗与用户对授权的理解度。

### 阶段 C：可靠通知与规模化

仅在朋友自用确有需要时评估离线推送、Capacitor/React Native 后台定位、端到端加密及更多受邀成员；不以扩大用户规模为默认目标。

## 20. 待确认问题

2. 产品最低年龄与未成年人使用政策是什么？
3. 单好友共享是否默认开启，还是每次建立好友后单独确认？建议单独确认。

## 21. 外部平台约束与参考

- Render Static Site 适合托管本项目的纯前端构建，SPA 需要 `/*` 到 `/index.html` 的 rewrite：[Static Sites](https://render.com/docs/static-sites)、[Redirects and Rewrites](https://render.com/docs/redirects-rewrites)。
- Render 当前计算区域包括新加坡但不包括中国大陆；Static Site 使用全球 CDN，实际跨境质量仍需实测：[Regions](https://render.com/docs/regions)。
- Supabase 当前可选亚洲数据库区域包括新加坡、东京和首尔，没有中国大陆或香港区域：[Available regions](https://supabase.com/docs/guides/platform/regions)。
- Supabase Realtime 生产环境应使用私有频道和 RLS；Broadcast 适合高频事件，Presence 适合在线状态：[Getting Started with Realtime](https://supabase.com/docs/guides/realtime/getting_started)、[Presence](https://supabase.com/docs/guides/realtime/presence)。
- 通过数据库发送的 Broadcast 会进入 `realtime.messages` 并保留一段时间，因此实时位置必须使用客户端 Broadcast 且关闭 replay：[Broadcast](https://supabase.com/docs/guides/realtime/broadcast)。
- Supabase 手机登录需要另行配置短信供应商；朋友自用版本因此选择预创建邮箱账号：[Phone Login](https://supabase.com/docs/guides/auth/phone-login)。
- Supabase Free 项目低活动约 7 天后可能暂停，可从 Dashboard 恢复；朋友自用需接受该免费档限制：[Project Pausing](https://supabase.com/docs/guides/platform/free-project-pausing)。
